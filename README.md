## Назначение проекта

Веб-приложение предназначено для автоматизации одной гостиницы: учета номеров, бронирования, заселения, продления проживания, выезда, уборки и управленческой отчетности.

Пять ролей: администратор, сотрудник службы приема и размещения, гость, сотрудник службы уборки и руководитель.

## Состояние и следующие этапы

### 2. Разработка моделей данных

Подготовлены логическая и физическая модели, словарь 65 полей, схема из 10 таблиц и SQL-примеры. Создана база `hotel_booking_web`; пройдена 51 регрессионная проверка, повтор установки и тест параллельного бронирования. [Открыть второй раздел](docs/02-data-models/README.md).

### 3. Проектирование архитектуры системы

Предстоит описать слои приложения, безопасность, UML-диаграммы и макеты интерфейса. Материалы будут размещены в `docs/03-architecture/`.

### 4. Разработка и реализация системы

Предстоит реализовать вход и роли, номерной фонд, бронирование, проживание, уборку, отчеты и почтовые уведомления. Описание реализации будет размещено в `docs/04-implementation/`; инструкции по сборке и запуску появятся вместе с кодом.

### 5. Тестирование системы

Предстоит проверить бизнес-логику, права доступа, целостность данных и сквозные сценарии. План и результаты испытаний будут размещены в `docs/05-testing/`.

## Планируемые технологии

Java 21, Spring Boot 3.x, Spring MVC, Spring Data JPA, Spring Security, PostgreSQL, Thymeleaf, Bootstrap и Maven; тестирование — JUnit 5 и Mockito.

## Порядок ведения проекта

Эта страница служит общей точкой входа. Разделы хранятся отдельно в `docs/`; новые материалы добавляются в свой каталог и получают прямую ссылку в таблице выше.

Этапы готовятся в отдельных ветках и объединяются с `main` после успешных проверок. Преподаватель может просматривать готовые материалы на главной странице. Готовность базы данных не означает готовность веб-приложения.
